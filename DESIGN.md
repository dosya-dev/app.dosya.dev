# dosya.dev app

## Overview

This documents the **authenticated app** at `app.dosya.dev` (`apps/web`), which is a
different design system from the marketing site documented in the repository-root
`DESIGN.md`. Both are dosya.dev; they do not share a type ramp, a palette, or a font.

| | Marketing site (`/DESIGN.md`) | App (this file) |
|---|---|---|
| Mode | Persuade | Operate |
| Type | System sans, fluid `clamp()` | Space Grotesk, fixed px ramp |
| Palette | Achromatic (Vault Ink, Stone Field) | Blue-tinted neutrals, seal-green primary |
| Density | Marketing whitespace | Dense: tables, rails, panels |

Applying the marketing ramp here is the single most common false signal from
automated design review. The app has ~1,100 uses of Tailwind's `text-xs`/`text-sm`
and ~430 uses of sub-12px literal steps; none of those are drift.

The source of truth for tokens is [`src/index.css`](src/index.css). Where this file
and that file disagree, the CSS wins and this file is stale.

## Colors

Achromatic is the marketing site's decision, not this one. The app's neutrals carry a
deliberate blue tint (hue ~240) so that surfaces, borders and muted text separate from
each other in dense tables without needing extra weight.

- **Primary is seal green** (`oklch(0.6236 0.1833 147.4139)`), used for the committed
  action, the active nav item, confirmation checks and live-state dots. One primary
  action per view.
- **Muted** is both the secondary surface and the track colour for meters and bars.
- **Destructive** is reserved for irreversible actions (revoke, delete) and never for
  emphasis.
- **chart-1..5** are the categorical chart ramp. A chart with two series should prefer
  a restrained pair (one neutral, one accent) over two categorical hues; see
  `--share-opens` / `--share-downloads`, which are validated for CVD separation
  against both surfaces rather than chosen by eye.

### Two functional palettes sit outside the theme tokens

These are literal hex values on purpose, because they must stay constant across all
eight themes: a PDF tile is the same blue in mono as in the default theme, and a
storage meter turning red must not be re-tinted by a theme choice.

- **`status-*`** drives meters, quotas and health indicators: green under 70%, amber
  over 70%, red over 90%. Always paired with a label or icon, never colour alone.
- **`filetype-*`** is the extension-to-colour map in
  [`src/lib/helpers.ts`](src/lib/helpers.ts) (`EXT_COLORS`) that tints file tiles and
  avatars. Adding a format means adding it there, not inventing a colour at the call
  site.

The `accent-*` entries are the long tail used by workspace icon pickers and category
chips. A new colour that is not one of these needs a reason; reach for a token first.

**Dark is selected, not flipped.** Every dark step is its own value re-picked against
the dark card surface. Base and text sit off pure black and pure white on purpose: the
dark theme was deliberately pulled back from maximum contrast after testers reported
halation, and that must not be "fixed".

Additional themes (`[data-theme="mono"]` and siblings in `index.css`) override the
neutral ramp only; they inherit `--chart-*` from `:root`.

## Typography

**One family carries everything**: Space Grotesk for UI, Space Mono for data. Mono is
for values that are read as measurements or identifiers, never as a "technical" costume:
byte counts, percentages, hashes, tokens, IDs, axis ticks.

The ramp is **fixed px, not fluid**. Users are at a consistent DPI inside a task; a
`clamp()` heading that shrinks inside a sidebar looks worse, not better.

| Step | Size | Where it lives |
|---|---|---|
| display / headline / title | 36 / 30 / 24px | Page-level statements, rare |
| page-title | 20px | The `h1` on a route |
| section | 18px | Sub-headings inside a page |
| panel-title | 15px | Card and panel headings |
| body | 16px | Prose, dialog copy |
| body-compact | 14px | The workhorse: most UI text |
| row | 13px | Table rows, buttons, list items |
| label | 12px | Secondary labels, help text |
| meta | 11px | Timestamps, counts, captions |
| micro | 10px | Uppercase table headers, badges, rail headings |
| micro-tight / tile | 9 / 8px | Avatar initials, file-type tiles |

The sub-12px steps are not an accident of ad-hoc styling. They are the app's real
micro-label ramp - 198 uses of 11px and 161 of 10px - and they exist because a file
table has to carry a name, a size, a timestamp, a region, a status and an owner in one
row. Uppercase micro labels take `0.07em` tracking; without it they close up and stop
being scannable.

Measure applies to prose (65-75ch). Tables and dense panels run wider.

## Layout

- **Shell:** fixed sidebar (~230-256px) plus a fluid content column. Some pages add a
  persistent right rail at ~316px for controls and summaries.
- **Page padding:** 32px on desktop, 16-18px below `900px`.
- **Rhythm:** 20px between major panels; 24px inside a card; 16px in dense grids.
- Responsive behaviour is **structural** (collapse the sidebar, drop the rail below the
  main column, let wide tables scroll in their own container), never fluid typography.
- Wide content scrolls inside its own `overflow-x-auto`; the page body never scrolls
  sideways.

## Elevation & Depth

**Border-first, flat at rest.** A 1px border defines a surface. Shadow is a response to
state (hover, focus, drag) or genuine float (dropdown, popover, dialog, toast), not a
property of a card sitting still.

In dark mode the ladder inverts: borders weaken and the surface ramp
(background → card → raised) carries elevation tonally. Raise a surface a step rather
than adding a heavier shadow.

## Shapes

Base radius is `0.75rem`. In practice the app uses Tailwind's own scale, and the four
that matter are `rounded-full` (avatars, pills, dots, status badges), `rounded-lg`
(buttons, inputs, nav items), `rounded-md` (small controls, inline code) and
`rounded-xl`/`rounded-2xl` (cards and panels).

Borders are 1px throughout. No thick or one-sided accent borders.

## Components

Every interactive component ships `default`, `hover`, `focus`, `active`, `disabled`,
and where it fetches, `loading`, `error` and `empty`.

- **Buttons** are 36px (32px small), `rounded-lg`, label at 13px/500. Primary is a
  seal-green fill; outline is card background with a 1px border; destructive actions use
  an outline with destructive text, reserving the solid fill for the confirm step inside
  a dialog.
- **Cards and panels** are `rounded-2xl` with a 1px border, flat at rest, 24px padding
  (18px in the rail).
- **Tables** use a muted header strip with 10px uppercase tracked labels, 1px row
  separators, and a hover tint. A clickable row also needs a real link on its primary
  cell, or keyboard users cannot reach the destination.
- **Loading** is skeletons shaped like the content, never a centred spinner.
- **Empty states** teach the surface: what it is for, and the action that fills it.
- Overlays escape their container (`dialog`, popover API, or a portal); an absolutely
  positioned menu inside an `overflow` ancestor gets clipped.

## Do's and Don'ts

### Do
- Read tokens from `src/index.css`; treat this file as documentation of it.
- Use the fixed px ramp above, including the sub-12px steps, in dense UI.
- Keep Space Mono for data, identifiers and measurements.
- Define surfaces with a 1px border and leave them flat at rest.
- Reserve seal green for the committed action and for confirmation.
- Re-pick dark values against the dark surface instead of flipping light ones.
- Give every fetching component a skeleton, an empty state and an error state.

### Don't
- Apply the marketing site's ramp, palette or font to this app.
- Introduce fluid `clamp()` type in product UI.
- Add a resting shadow to a static card, or compensate for dark mode with a heavier one.
- Raise dark-mode contrast toward pure black and pure white.
- Use a chart's categorical hues where a neutral-plus-accent pair would read better.
- Ship a clickable row whose only affordance is a row-level `onClick`.
- Imply anywhere in copy that dosya.dev reads, scans or inspects file contents.
